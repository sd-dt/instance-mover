# 界面截图说明（真实性与出处）

本目录全部截图都是 **Minecraft 26.2 开发客户端（`gradlew runClient`）真实运行**时，
用**游戏内置 F2 截图功能**抓取的原图，尺寸均为 **1260×700**（客户端窗口 1260×700）。

* **没有做任何合成、拼贴、拉伸或文字补画**；没有截图被裁剪或重命名后冒充别的界面。
* 截图里的所有文字、数字、体积、路径都来自当次真实运行（老实例 = 开发者自己造的演示实例）。
* 场景中的「老实例」是截图专门造的演示数据（见下方「演示数据」），不是玩家的真实存档。
* 本目录里的 `*-放大.png` 是对应截图的**局部 2 倍最近邻放大**（只为看清文字，未做任何文字补画），
  原图在同目录同名（不带 `-放大`）的文件里。

> **2026-10-01 t18 复拍**：M4 交付时登记的三处外观缺陷（关于页/结果页多行文本叠印、主界面条目行类型词重复）
> 修复后，本目录的 `00`、`01`、`02`、`03`、`04`、`05`、`08` 与 `06`、`07` 全部**重新出图**替换。
> 复拍会话的 GUI 缩放为 **2**（当次 `run\options.txt` 的 `guiScale:2`），所以版面比 M5 首版更紧凑、
> 每页列表行数更少（主界面共 13 页），但**显示内容、页码与数值都是当次真实运行的**。

## 二、演示数据（截图场景怎么造的）

截图用的开发运行目录是 `D:\1sd_dt\statu\run`，其中造了两套「老实例」模拟 PCL2/HMCL 的版本隔离结构：

```
run\versions\老整合包-26.1\      ← 老实例 1：100 个文件 / 126 MB（saves 带两个存档、24 个 region 文件、
  ├─ saves\世界A\...                 42 个 config、shaderpacks、resourcepacks、xaero、journeymap、XaeroPlus、
  ├─ config\mod_*.toml               .voxy、Distant_Horizons_server_data、replay_recordings、CustomSkinLoader、
  ├─ options.txt / servers.dat …     tacz、mods、defaultconfigs、PCL、hmcl.json、optionsshaders.txt、
  └─ …（故意缺 screenshots /        iris.properties、command_history.txt；
        schematics / optionsof.txt） 故意缺 screenshots、schematics、optionsof.txt、essential）
run\versions\老整合包-26.0\      ← 老实例 2：3 个文件（用于验证下拉切换候选）
```

生成脚本：`.t13-shots\Make-DemoData.ps1`；截图会话的 Gradle init 脚本：`.t13-shots\shots-run.gradle`
（这两个路径在**开发工作区** `D:\1sd_dt\statu\` 下，不在 release 目录里；前者把 `-Dinstance_mover.forceGui`
与窗口尺寸真正注入到游戏 JVM，用法见 [使用说明.md](../使用说明.md) 第十二节）。

**t18 复拍为了抓进度页**，临时往老实例 1 的 `saves\世界A\region`（默认勾选条目）里加了 16 个 64 MB 的数据文件，
让迁移耗时从 0.8 秒拉长到几秒，才抓到 `06-进度页.png`；**截图会话结束后已删除这些临时文件**
（`run\xaero\lod-cache` 里被一并转移出去的那份也删了），`run\` 里还清掉了 `_转移备份_*` 备份目录与
`run\config\instance_mover.json` 标记文件，`run\versions\` 保持上面的演示数据。`run\logs\` 与 `run\screenshots\`
（本目录文件的原始出处）保留作为运行记录。

### 复拍时怎么驱动界面（便于以后重做）

* 窗口尺寸/注入参数：`gradlew.bat -I .t13-shots\shots-run.gradle -I init-redirect.gradle runClient [-PimForceGui=false]`
  （`-PimForceGui=false` 时靠「删掉标记文件」实现真正的首次自动弹出，`00` 就是这样抓的）。
* 截图：给游戏窗口发 **F2**（`keybd_event` VK 0x71），原图落在 `run\screenshots\`；脚本在 `.t18probe\Shoot8.ps1`。
* 点击坐标：**GUI 空间坐标**（窗口逻辑尺寸 630×350），不是截图像素坐标 —— 截图是 2 倍 DPI 下的
  framebuffer（1260×700），把截图坐标直接拿去点会偏一倍，本轮就是这么踩过坑的。

## 三、没有截到的界面（如实说明）

| 界面 | 为什么没有截图 |
|---|---|
| 中止后的「已取消」结果页 | 需要在迁移中途点「中止」并抢在完成前截图；迁移很快（126 MB 只用 0.8 秒），来不及（功能已由单测 `TransferRunnerTest > 取消：能中止转移` 与自检覆盖） |
| 「出错了」结果页 / 失败清单 | 需要构造真实的复制失败（占用/权限），本次没有故意制造失败场景 |
| 「备份不完整」警告 | 同上，需要构造备份失败（功能已由 `BackupService` 的警告日志与 `TransferReport.backupIncomplete()` 覆盖，见 t15 交付报告） |
| 「稍后再说」/「不再提示」的落盘效果 | 行为已由单测 `FirstRunGateTest` / `MoverConfigTest` 覆盖，截图上体现为界面消失，无独立界面 |

> 这些界面都没有伪造截图；如需补充，可在有交互显示环境的会话里按上面「复拍时怎么驱动界面」的做法复现。
