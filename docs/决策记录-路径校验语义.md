# 决策记录：路径校验语义（t14 / F1）

> 背景：审查 t6 提出 blocker F1 —— `TransferRunner.validatePaths` 把「源/目标互为父子」整体拒绝，
> 导致用户选定的核心场景（探测 `versions\` 下所有版本实例）在两种最常见隔离布局下 100% 无法迁移。
> 队长派 t14 返修后，实现者指出**队长写的验收标准内部自相矛盾**，请求裁决。本文件是该裁决的正式记录。
> （系统不允许修改已终态任务的契约，故以本文件作为下游审查/验证的对齐依据。）

## 一、矛盾的原文

t14 原验收标准里同时存在：

- ② 「老实例 = `.minecraft` 根 / 当前实例 = `versions\新包` **及反向**都能通过校验且迁移成功」；
- ③ 「`src.startsWith(dst)` 整体拒绝仍在」。

而 ③ 的情形**恰好就是 ② 的「反向」**（老实例 `versions\旧包` 位于当前实例 `.minecraft` 根内部）。
两者不可能同时 100% 满足。**这是队长验收标准的错误，不是实现的错误。**

## 二、队长裁决的依据（重新推演）

设 `src` = 老实例根，`dst` = 当前实例根；迁移按条目进行，25 个条目名都是**固定常量**，
所以每条迁移的源/目标是 `src/<条目名>` → `dst/<条目名>`。

| 情形 | 具体例子 | 是否真的自我复制 | 裁决 |
|---|---|---|---|
| **A**`src` 落在 `dst` 内，但**不在任何条目目录**里 | `src=.minecraft\versions\旧包`、`dst=.minecraft`（`dst\versions` 不是迁移条目） | **否**：`src\config → dst\config`、`src\saves → dst\saves`、`src\options.txt → dst\options.txt`，没有任何一条落进自己的子树 | ✅ **放行**（这正是用户的核心场景） |
| **B**`src` 落在**某个条目目录**内部 | `src=<当前实例>\config\backup`（条目 `config`） | **是**：整棵源树会被复制进自己的子树 | ❌ **整体拒绝**（保留） |
| **C** 条目目标落在其源内部 | 某条目 `dstItem` 位于 `srcItem` 内 | **是**（该条目层面） | ✅ 放行整体校验，由**条目级守卫**只跳过该条 |

结论：真正需要整体拒绝的只有 **B**。验收标准 ③ 收窄为
**「源根落在某个待迁移条目目录内部时整体拒绝」**；② 的「及反向」保持不变。

## 三、落地实现（已核验）

| 位置 | 行为 |
|---|---|
| `TransferRunner.validatePaths(Path,Path)`（约 :84-99） | 只拒绝：源/目标为空、任一侧不存在或不是文件夹、**同一个目录**（`PathUtils.sameDirectory`：去 `\\?\` 前缀 + 大小写不敏感 + `Files.isSameFile`） |
| `TransferRunner.validatePaths(Path,Path,List)`（约 :112-127） | 在上一级基础上，仅当 `src` 落在**某个待迁移条目目录**内部时整体拒绝 |
| `TransferRunner.run()` 条目循环（约 :230-235） | 条目级守卫：`PathUtils.isInside(dstItem, srcItem)` → 只跳过该条、`failed++` 并记中文原因，**不删除、不覆盖目标数据**，其余条目照常 |

## 四、验收证据（t14 自证 + 队长独立核验）

- 正向端到端：老 = `.minecraft` 根 / 当前 = `versions\新包` → created=3、failed=0、目标独有 `config/keep.toml` 保留、`.part` 残留 0；第二次 skipped=3、over=0（幂等）。
- **反向端到端**：老 = `versions\旧包` / 当前 = `.minecraft` 根 → created=3、failed=0、目标独有文件保留、源树完好；第二次幂等。
- 条目级嵌套：目标落在源内部时该条 failed=1、目标零写入、源数据原样，同一次 run 中 `config` 条目照常 created=1。
- 队长独立核验：`tests=128 failures+errors=0`；jar 121,955 字节；`TransferRunnerTest` 内含上述两条端到端与条目级守卫用例。

## 五、给下游审查/验证的明确指令

1. **不要**按 t14 契约里 ③ 的字面（`src.startsWith(dst)` 即拒）判定失败——该条已被本记录收窄。
2. 需要验证的是：A 情形放行且迁移成功；B 情形整体拒绝；C 情形只跳过该条目且目标数据零改动。
3. 若认为本裁决仍有风险，请带具体反例（路径组合 + 期望行为）提出，队长再裁。
