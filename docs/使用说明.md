# 使用说明 — 实例酱的搬家服务（instance_mover）v1.0.0

> 一个 **Minecraft 26.2 Fabric 客户端模组**：第一次进入整合包时在主界面弹出中文界面，
> 自动探测同一个 `versions\` 隔离目录下的其他版本实例（也可以手填/浏览路径），
> 勾选要迁移的玩家数据后**合并覆盖**到当前实例；配置类文件覆盖后会提示需要重启。
> 迁移逻辑与清单对齐 `D:\1sd_dt\versionchanger`（MC 实例数据转移工具 v1.1）。
>
> 配套文档：[迁移清单.md](迁移清单.md)（25 项逐条说明）· [工作流.md](工作流.md)（需求与决策定稿）
> 界面截图：[release/screenshots/](release/screenshots/)

## 一、运行要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 游戏版本 | **Minecraft 26.2**（Java 版 Chaos Cubed） | `fabric.mod.json` 里写死 `minecraft: 26.2` |
| 模组加载器 | **Fabric Loader ≥ 0.19.5** | 低于该版本无法加载 26.2 模组 |
| 前置模组 | **Fabric API**（对应 26.2 的版本，实测 0.159.0+26.2） | 必须装，否则模组不生效 |
| Java | **Java 25 或更高**（26.2 的最低要求） | 启动器一般会自动用对 |
| 端 | **仅客户端** | 服务端不需要装，装上去也不会加载 |

## 二、安装方法

1. 把 `release\instance-mover-fabric-26.2-1.0.0.jar` 复制到**要搬进的那个实例**（新整合包）的 `mods` 目录：

   | 启动器模式 | 放哪里 |
   |---|---|
   | 版本隔离（PCL2 / HMCL 默认） | `.minecraft\versions\<新整合包版本名>\mods\` |
   | 非隔离（共用 `.minecraft`） | `.minecraft\mods\` |
2. 确认同目录里还有 **Fabric API** 的 jar。
3. 启动游戏。**第一次**进到主界面（标题界面）时，模组会自动弹出「玩家数据迁移 v1.0」界面。

> 模组不需要任何外部工具、不联网、不写注册表；玩家数据探测与复制全部是本机文件操作。

## 三、首次进入会发生什么（首启流程）

```
启动游戏 → 加载完成、停在主界面
        → 自动弹出「玩家数据迁移」界面（只弹一次，不打断进行中的游戏）
        → 选老实例 → 勾选内容 → [开始迁移]
        → 进度页 → 结果页（含「需重启」提示）→ 完成
```

界面底部的三个按钮决定「以后还弹不弹」：

| 按钮 | 行为 | 是否落盘 |
|---|---|---|
| **开始迁移** | 先记住本次选择的老实例，再进入进度页；迁移成功后写 `firstRunDone=true` | 是 |
| **稍后再说** | 本次游戏不再弹，**不写标记、不落盘**；关掉游戏下次进来还会弹 | 否 |
| **不再提示** | 写 `firstRunDone=true`，以后不再弹 | 是 |

**标记文件**：`<实例目录>\config\instance_mover.json`（UTF-8 JSON，原子替换写入，损坏/缺失一律回退默认值，不会让游戏崩）

```json
{
  "firstRunDone": true,
  "lastSource": "D:\\...\\.minecraft\\versions\\老整合包-26.1",
  "backupEnabled": true,
  "skipSameEnabled": true
}
```

| 字段 | 含义 |
|---|---|
| `firstRunDone` | 是否已经处理过首次提示（`true` = 不再自动弹） |
| `lastSource` | 上次选的老实例路径（下次打开界面优先选它） |
| `backupEnabled` | 「迁移前先备份」开关的持久化值 |
| `skipSameEnabled` | 「跳过内容完全相同的文件」开关的持久化值 |

> 想让它**再弹一次**：删掉这个文件（或把 `firstRunDone` 改成 `false`）。
> 想在开发/排障时**强制弹**：加 JVM 参数 `-Dinstance_mover.forceGui=true`（见第十节）。

## 四、主界面逐块说明

界面分三段 + 底部按钮：

### ① 选择老实例

| 控件 | 作用 |
|---|---|
| 顶部深色长条（下拉） | **自动探测**到的版本实例，点一下循环切换（鼠标悬停有提示）。不显示当前实例自身 |
| 「已探测到 N 个版本实例」 | 探测结果条数 |
| 路径输入框 | 可直接**粘贴**路径，或由下拉/浏览自动填入 |
| **[浏览…]** | 游戏内目录选择器：列出子文件夹，双击进入、[上一级]、[选择此目录]（26.2 原版没有目录选择框，这里做成纯游戏内浏览，不调用 AWT） |
| **[检测]** | 按输入框里的路径做校验并重新扫描 |

探测范围：**当前实例所在的 `versions\` 目录下的每一个版本文件夹**，命中条件 = 目录里含 `saves` 或 `config`（只含 `mods` 的目录不算）。
候选按「有存档 → 有配置 → 名字」排序；体积估算**限量限时**（每项最多 3000 个文件 / 0.5 秒），不会卡界面。

校验规则（不满足会给红字并清空已选）：

* 路径必须是**存在的文件夹**；
* 必须含 `saves` 或 `config`，否则提示「没有找到 saves 或 config，不像一个游戏实例」；
* 不能等于**当前实例自身**；
* 如果你选的是**含 `.minecraft` 的上一层**，会自动下钻到 `.minecraft` 并提示「所选目录里没有实例文件，已自动改用子目录：…」。

状态行示例：`状态：✔ 含 saves 2 个、config 43 项、共 126.0 MB / 100 个文件`
（非隔离根目录会补一句「（体积不含 versions\）」，避免把每个版本实例重复算进去）

### ② 选择要迁移的内容

分三段显示（详见 [迁移清单.md](迁移清单.md)）：

1. **默认直接迁移（N 项）** —— 老实例里存在、默认就迁移的项；
2. **额外玩家信息（老实例中检测到，可勾选）** —— 询问项**只列出老实例里真实存在的**，各自带默认勾选态；
3. **老实例中未找到（自动跳过）** —— 缺失或类型不符的默认项，只提示、不复制（原因：「不存在」/「类型不符」）。

按钮：**[全选] [反选] [仅默认]**；列表分页（[上一页]/[下一页] + 「第 x / y 页」，每页行数随窗口高度自适应）。
每行格式：`名称（类型，体积说明）（需重启生效）`，鼠标悬停显示这一项的作用。底部实时显示「已勾选 N 项（约 X）」。

### ③ 选项

| 选项 | 默认 | 说明 |
|---|---|---|
| 迁移前先备份到「_转移备份_日期_时间」 | 勾选 | 迁移前把**当前实例里会被覆盖**的内容备份一份，见第七节 |
| 跳过内容完全相同的文件 | 勾选 | 内容和目标一样就跳过，第二次跑几乎瞬间完成（幂等） |

底部按钮：**[开始迁移] [稍后再说] [不再提示] [查看每项作用] [关于]**
「查看每项作用」= 25 项清单的作用说明，分页浏览；「关于」= 模组名、版本、作者、mod id。

## 五、迁移时的进度页

点「开始迁移」后切到进度页，三个阶段依次跑（后台线程，界面不卡）：

1. `正在统计文件…` —— 统计本次要复制多少文件、多大体积；
2. `正在备份新实例中将被覆盖的内容…` —— 只在勾了备份时出现；
3. `正在转移数据…` —— 逐项复制，显示进度条「已完成 x / y 个文件」、写入体积、最近几行日志（含每项的「新增 / 覆盖 / 相同跳过」统计）。

**[中止]**：立即停止，**已复制的内容不会回滚**（重跑一次即可，相同内容会自动跳过）。
转移过程中 ESC 不会误关界面，必须点「中止」。

## 六、结果页

| 显示 | 含义 |
|---|---|
| 成功 N（新增 a / 覆盖 b） | 成功复制的文件数（新增 = 目标本来没有；覆盖 = 目标有但内容不同被替换） |
| 跳过 N | 内容完全相同、按开关跳过 |
| 失败 N | 单个文件失败（不中断整体） |
| 写入 X / 耗时 Y 秒 | 本次实际写入体积与耗时 |
| 备份目录：… | 本次备份目录（没勾备份则不显示） |
| 老实例中缺失、已跳过：… | 老实例里没有的条目名 |
| 没有失败文件 / 失败清单 | 有失败时列出前 6 条，「[复制失败清单]」一键复制全部失败原因 |
| 备份不完整的警告 | 备份阶段有文件没备份成功时给醒目提示，请手动检查备份目录 |

按钮：**[打开备份目录]**（备份存在时）、**[复制失败清单]**（有失败时）、**[完成]**；涉及配置类条目时额外显示「需要重启游戏」提示与 **[退出游戏]**。

## 七、备份机制

* 目录名：`<当前实例>\_转移备份_yyyyMMdd_HHmmss\`（例如 `_转移备份_20261001_050826`）；同名已存在时自动追加 `_1`、`_2`…
* **只备份「当前实例里已经存在、且本次会被覆盖」的条目**（`todo = 目标侧存在的条目`）；目标里一个同名条目都没有时不会建备份目录；
* 备份**不做「相同跳过」**（备份必须真拷一份），保证备份里是**覆盖前的旧内容**；
* 备份统计并入总统计，并且**不计入「覆盖」**（备份目录是新建的，全部算新增）；
* 备份失败**不中断**迁移，结果页会给「备份不完整」警告。
* 还原方法：把备份目录里的内容复制回实例目录即可（结构与实例一致）。

## 八、失败处理

* 单个文件失败**不会中断**整个迁移，会记成 `复制失败：<源> → <目标>（原因）` 进失败清单；
* 失败清单可在结果页一键复制，便于排查；
* 常见原因与对策：

| 现象 | 原因 | 对策 |
|---|---|---|
| 「拒绝访问」/「另一个程序正在使用此文件」 | 文件被游戏或杀软占用 | 关掉**老实例**的游戏再迁移；杀软白名单 |
| 只读文件覆盖失败 | 文件属性是只读 | 模组会先清只读属性；若仍失败，手动去掉只读 |
| 路径过长 | Windows 260 字符限制 | 模组对目标路径自动加 `\\?\` 前缀；源路径过长时建议缩短目录层级 |
| 类型冲突删除失败 | 目标是同名文件夹/文件且删不掉 | 该项记失败并跳过（**不会静默删数据**），手动处理后重跑 |
| 备份不完整警告 | 备份阶段有文件失败 | 迁移已完成，但请先手动检查备份目录再用 |

* 迁移是**幂等**的：重跑一次，内容相同的文件会跳过，只补齐没成功的部分。

## 九、需重启生效（配置类条目）

本次覆盖了以下 6 项之一时，结果页会给出「需要重启游戏」提示（金色）+「退出游戏」按钮：

`config`、`options.txt`、`optionsshaders.txt`、`iris.properties`、`optionsof.txt`、`defaultconfigs`

**原因**：这些文件在游戏启动时已被读进内存。数据类（`saves` / `screenshots` / `.voxy` / DH 数据…）迁移后立刻有效，
但配置类如果**不重启就直接退出游戏**，游戏会在退出时把内存里的旧配置写回磁盘，把刚迁移进来的内容覆盖掉。

**做法**：在结果页点「[退出游戏]」→ 重新启动整合包 → 新配置生效。
（先点「[打开备份目录]」确认备份存在再退出，更稳妥。）

## 十、常见问题（FAQ）

**1. 界面没有弹出来？**
只在**停到主界面（标题界面）且不在世界里**时弹一次。请确认：模组与 Fabric API 都在 `mods` 里、游戏是 26.2、Java ≥ 25；
若上次点过「稍后再说」，本次不会弹（重启游戏仍会弹）；若标记文件里 `firstRunDone=true`，把文件删掉或改成 `false`。
排障可加 JVM 参数 `-Dinstance_mover.forceGui=true` 强制弹（PCL2/HMCL 的「JVM 参数」里加；开发用 `gradlew runClient` 时见第十二节）。

**2. 没探测到老实例 / 只探测到一个？**
探测范围是**当前实例所在的 `versions\` 目录**。如果老整合包在别的 `.minecraft` 里（不同启动器、不同游戏目录），
自动探测肯定看不到 —— 用**手填路径**或 **[浏览…]** 选到老实例根目录，再点 **[检测]**。

**3. 「没有找到 saves 或 config，不像一个游戏实例」？**
选中的目录不是实例根目录。实例根目录里应该有 `saves` 或 `config`（`mods`/`versions` 不算）。
如果你选的是含 `.minecraft` 的上一层，会自动下钻。

**4. 「这就是当前实例本身，请选择另一个」？**
你选的是正在运行的这个实例，换一个。

**5. `mods`（模组本体）要不要勾？**
默认**不勾**，一般也不建议：老实例的模组 jar 覆盖过来后，版本/加载器不匹配可能直接启动崩溃。

**6. 迁移后配置没生效 / 又被改回去了？**
见第九节：配置类要**重启**；不重启直接退出，游戏会把旧配置写回去。

**7. 提示存档含 `session.lock`？**
说明那个存档可能正被另一个游戏进程占用（老实例的游戏还开着）。**先关掉老实例的游戏**再迁移，否则存档可能不完整。

**8. 迁移到一半点了中止 / 断电了怎么办？**
已复制的内容保留，**不会回滚**；重新点一次「开始迁移」即可，相同内容会自动跳过。写盘用「临时文件 + 原子替换」，不会留下半个文件。

**9. 会不会把新实例里的东西删掉？**
不会。文件夹是**合并覆盖**：同名文件才覆盖，**新实例里独有的文件/文件夹原样保留**。
唯一会删除的是「同名但类型不同」的那个条目（源是文件夹、目标是同名文件，反之亦然），日志和结果页都会记录。

**10. 体积为什么显示「约 X GB（未扫完）」？**
体积估算有上限（每项 3000 个文件 / 0.5 秒），超了就标「未扫完」——只影响显示精度，**不影响迁移**。

**11. 界面为什么只有中文？**
按项目口径只提供中文界面。`assets/instance_mover/lang/en_us.json` 仅为兼容英文语言环境而存在，内容与 `zh_cn.json` 完全相同。

**12. 服务端要不要装？**
不用，这是客户端模组（`environment: client`）。

**13. 支持哪些启动器？**
探测基于 `versions\<版本名>\` 这一通用约定（PCL2、HMCL、官方启动器都符合）；非隔离实例可以直接手填路径。

**14. 迁移会联网/上传数据吗？**
不会。全部是本机文件复制，模组没有任何网络访问。

## 十一、调试开关（排障用）

| JVM 参数 | 作用 |
|---|---|
| `-Dinstance_mover.forceGui=true` | 无视标记文件，强制弹出主界面（调界面/排障用；仍需停在主界面） |
| `-Dinstance_mover.selftest=true` | 只跑**引擎自检**（在系统临时目录里跑一遍真实复制/备份/取消流程），日志输出 `[自检] …` 与 `SELFTEST PASS n/n`，**不弹界面、不碰玩家数据** |

日志位置：`<实例目录>\logs\latest.log`，模组日志前缀是 `instance_mover`。

> **关于「首次进入的迁移引导」什么时候会弹（t22/t23 起）**
>
> - **第一次进入**（该实例还没有 `config\instance_mover.json` 时）会在标题界面弹出迁移引导；
> - **完成一次真实迁移后，下次启动不再自动弹出**（按方案 b：搬完就安静，不反复打扰）；取消、失败、中止都**不**写入标记，下次仍会弹；
> - **想重新看到引导**：在游戏里打开「**关于**」页，点「**重新显示迁移引导（下次启动生效）**」即可，**不需要**去手动改或删 `config\instance_mover.json`（当然删掉该文件同样有效）；
> - 标记文件只在两种情况下被写成「已提示过」：玩家点了「**不再提示**」，或完成了一次**真实的成功迁移**——界面从未弹出时绝不会被悄悄写入。
>
> **整合包作者注意**：分发整合包时请把 `config\instance_mover.json` 排除掉（或确认它是 `firstRunDone: false`），否则玩家拿到 `true` 就永远不会看到迁移引导。
