## 二、需求理解（请重点核对这一节，我按这个做）

1. 模组随**新整合包**一起分发，玩家装上后**第一次进入**（进游戏时）**自动弹出一个界面**；
2. 界面里让玩家选：要从**老实例**迁移哪些玩家数据（沿用 v1.1 的默认项 + 可勾选额外项 + 缺失项提示 + 每项作用说明）；
3. 点「开始迁移」后，把**老实例目录**里选中的内容**合并覆盖**到**当前游戏目录**（=新整合包实例）；
4. 全程在游戏内完成，**不需要外部 exe**；迁移逻辑（备份、只读解锁、超长路径、同内容跳过、失败不中断）与 v1.1 一致；
5. 中文界面。

## 三、三个必须先定死的语义（我给出默认方案 + 备选）

### 3.1 「老实例」怎么来？

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A ✅ 已采纳** | 界面顶部一个路径输入框 +「浏览…」按钮。默认值由模组**自动探测**：列出**同一 `versions` 版本隔离文件夹下的所有版本实例**（PCL2/HMCL 隔离模式 = `.minecraft\versions\<版本名>\`），命中「含 `saves`/`config` 且不是当前实例」的候选，用下拉列表让玩家挑 | 通用，任何玩家都会用 |
| B ❌ | 只认整合包作者写死在配置里的固定路径 | 简单但只对一台机器有效 |
| C ❌ | 只让玩家手填/粘贴路径 | 最省事，但玩家容易填错 |

> **已采纳 A**：探测范围 = 当前实例所在的 `versions\` 目录下**每一个版本文件夹**（含非隔离的 `.minecraft` 根目录本身）；
> 同时保留手填/粘贴路径，并做校验（必须存在、必须含 `saves` 或 `config`、不能等于当前游戏目录）。
> 每个候选项显示：版本名、路径、体积、是否有存档 —— 方便玩家认出「哪个是老整合包」。

### 3.2 「第一次进入」怎么判定？

* 标记文件：`config/instance_mover.json`（整合包自带；玩家点「开始迁移」或「不再提示」后被改写）。
* **已采纳：触发时机 = 客户端主界面**（标题界面就绪后弹一次，不打断进行中的游戏）；玩家选「稍后再说」→ 本次游戏不再弹，下次进游戏再弹。
* **不选**「进存档时弹」：玩家可能直接进存档，弹窗压在世界加载上体验差。
* 调试开关：`-Dinstance_mover.forceGui=true` 无视标记强制弹窗（我自己测界面用）。

### 3.3 「配置类文件」的运行期陷阱（**这条必须你拍板**）

`config/`、`options.txt`、`optionsshaders.txt`、`iris.properties` 这类文件，**游戏启动时已经读进内存了**。
在游戏内做覆盖后：数据文件（`saves`/`screenshots`/`.voxy`）立刻有效；但配置类文件会被游戏在**正常退出时反向覆盖回去**。

| 方案 | 行为 | 取舍 |
|---|---|---|
| **A ✅ 已采纳** | 照常覆盖，但迁移完成后弹「**需重启**」提示页，并**建议玩家立刻退出游戏**（给出「退出游戏」按钮）；明确写清：不重启就退出，配置类改动可能被游戏覆盖回去 | 简单、可控 |
| B ❌ | 配置类文件延迟到「退出游戏后」再写（shutdown hook 落盘） | 不丢配置，但实现复杂、被杀进程时失效 |
| C ❌ | 数据类游戏内迁移；配置类只复制到 `config/instance_mover-pending/` + `一键应用.bat` | 最稳，但破坏「全在游戏内完成」的体验 |

## 六、工程结构（预规划）

```
D:\1sd_dt\statu\
├─ 工作流.md / 使用说明.md / 迁移清单.md
├─ gradle.properties  settings.gradle  build.gradle  init-redirect.gradle
├─ gradlew / gradlew.bat / gradle\wrapper\   ← 复制对标工程（含腾讯镜像、9.7.1）
├─ src\main\java\dev\sd_dt\instancemover\
│   ├─ InstanceMoverClient.java        客户端入口：注册 tick、首启判定、弹窗调度
│   ├─ engine\  CopyEngine / ScanService / FileEntry / TransferPlan / BackupService / TransferReport
│   ├─ model\   MigrateItem（名称/类型/作用/默认勾选/体积）/ MigrateCatalog（25 项清单）
│   ├─ gui\     MigrateScreen（主界面）/ ProgressScreen / ResultScreen / AboutScreen / PathFieldWidget
│   ├─ config\  MoverConfig（json 读写：标记位、上次源路径、备份开关）
│   └─ util\    SizeFormatter / PathUtils（\\?\ 长路径、只读解锁）/ InstanceScanner（versions\* 探测）
├─ src\main\resources\fabric.mod.json + assets\instance_mover\lang\{zh_cn,en_us}.json
├─ src\test\java\...  引擎单元测试（纯 Java，不需要启动游戏）
└─ release\  instance-mover-fabric-26.2-1.0.0.jar + 预览截图
```

**关键实现约束**（都是 v1.1 踩过的坑，直接继承）：
* 「文件是否相同」判定：≤4 MB 内容比对，超限保守重写（只比大小+时间会漏覆盖）；
* 合并覆盖：老实例有则覆盖，新实例独有则保留（存档不会被清空）；
* 目标路径用 `\\?\` 前缀处理超长路径；只读属性先清；被占用文件记录失败、继续跑；
* 复制走临时文件 + 原子替换，避免「复制到一半游戏崩了」留下半个文件；
* 源目录存在 `session.lock`（老实例正在运行）时，对该存档给出明确警告。

## 七之二、开工前侦察结论（本轮实测，已写进任务契约）

| # | 实测结论 | 对实现的影响 |
|---|---|---|
| 1 | `curl.exe` 与 PowerShell/.NET 的 HTTPS **全部失败**（`SEC_E_NO_CREDENTIALS`，代理 `127.0.0.1:7897`） | 禁止用 PowerShell 下载任何东西；**Gradle 走 Java 自带 TLS，不受影响** |
| 2 | `C:\Users\sd_dt\.gradle` 在沙箱内**只读**（实测 `gradle-9.7.1-bin.zip.lck 拒绝访问`） | 必须把 `GRADLE_USER_HOME` 指到工作区内（`D:\1sd_dt\statu\.gradle-home`）；代价是**无法复用**对标工程已有缓存，首次构建要重新下载 |
| 3 | py 源码里 `.voxy`、`Distant_Horizons_server_data` **原属 `OPTIONAL_ITEMS`**（默认勾选），`DEFAULT_ITEMS` 只有 9 项、询问 16 项 | 按你的决定搬进默认项后 = **默认 11 / 询问 14**；py 自检里 `len(DEFAULT_ITEMS)==9`、`len(OPTIONAL_ITEMS)==16` 两个断言**必须同步改**，否则实现者会照抄错数字 |
| 4 | py 自检里价值最高的 9 类断言（含「大小+时间相同但内容不同必须覆盖」这个真实缺陷）已逐条提取 | 成为 Java 单测的必测清单 |

配套文件：**[移植基线.md](移植基线.md)** —— 25 项清单逐字文案 + py 全部行为/行号 + 环境硬约束，是本次移植的唯一真源。
